## url-scan 阻断政策变更（grill-with-docs 访谈产出）

- 决策：PR 新增链接「恶意」(malicious≥2) 与「可疑」(malicious==1 或 suspicious≥1) 现在**同等阻断合并**，且运行期**无任何人工放行**；白名单 (`.github/url-scan-allowlist.txt`) 是唯一、须预先经 PR 合入配置的例外。
- 经 grill 追问确认两点：① 字面执行现有可疑口径（不收紧到 suspicious≥2）；② 绝对化，连维护者都禁止绕过 required check。
- 产物：
  - `docs/adr/0003-suspicious-blocks-merge-no-runtime-override.md`（新 ADR）
  - `scripts/url-scan/CONTEXT.md`：更新「阻断」「白名单」术语（去除"仅恶意触发/可疑警告"）
  - `scripts/url-scan/README.md`：判定规则表可疑改为阻断；分支保护说明加 *Do not allow bypassing the above settings*
  - `scripts/url-scan/report.mjs`：失败判定从 `malicious>0` 扩为 `malicious>0 || suspicious>0`，改写报告文案与页脚规则、新增可疑检出明细
- 验证：`report.mjs` 对可疑-only 数据 dry-run 退出码 1（check 失败）。`scan-urls.mjs` 的 verdict 分类口径未动。
- 注意：本决策只动 url-scan（安全/阻断链路），不影响 link-check（存量有效性/issue/不阻断）的独立行为。

## url-scan 报告与进度评论双语化（grill-with-docs 访谈产出）

- 需求：给 URL 安全扫描报告加英文。经追问确认：① **段落式**排布（中文块在前、`---`、英文块在后，非行内并排）；② 覆盖**最终报告 + 进行中进度评论**。
- 实现（重构为「单一模板 `render(extracted,scan,t)` + 语言参数 `T.zh/T.en`」，DRY，中英共用取数逻辑）：
  - `scripts/url-scan/report.mjs`：双语渲染全部文案（标题/结论/表头/判定标签/明细折叠/说明/页脚规则），中英两半用 `---` 分隔；清理了无表格行时的双空行。
  - `scripts/url-scan/lib/progress-comment.mjs`：同结构双语（进行中/进度/表头/标签/页脚），中英分段。
- 术语：`CONTEXT.md` 新增「判定标签（Verdict label）」条目，固定中英配对：恶意/Malicious、可疑/Suspicious、安全/Clean、未扫描/Not scanned、待扫描/Pending、扫描中/Scanning；中英必须成对。
- 验证：两模块 `--check` 通过；`report.mjs` 对可疑/全绿两套数据 dry-run，文案双语正确、退出码分别 1/0；进度评论渲染样例正确。
- 未新建 ADR：双语排布易回滚、无实质权衡，按 domain-modeling「ADRs sparingly」跳过，仅沉淀 glossary。

## url-scan 增加手动一键重跑（workflow_dispatch）

- 需求：现有已生成报告的 PR 想重跑扫描（套用合入 master 后的新逻辑），原 workflow 仅 `pull_request_target`（opened/synchronize/reopened），无手动入口。
- 改动 `.github/workflows/url-security-scan.yml`：
  - 新增 `workflow_dispatch` 触发，带必填输入 `pr_number`（要重扫的 PR 编号）。
  - 三步 `PR_NUMBER` 统一改为 `${{ github.event.inputs.pr_number || github.event.number }}`（pull_request_target 走 event.number，手动触发走 inputs.pr_number）。
  - `concurrency.group` 同步改为 `url-scan-pr-${{ github.event.inputs.pr_number || github.event.pull_request.number }}`，保证两种触发都按 PR 分组且可取消在途。
- 同步 `scripts/url-scan/README.md`：第 7 行触发说明加 workflow_dispatch；新增「手动重跑」小节（Actions → Run workflow → 填 pr_number）并强调手动触发同样 checkout base 分支、须先合 master 才生效。
- 验证：pyyaml `safe_load` 通过（无解析错误，顶层 `on` 被归一为布尔 True 属正常）；确认两个 trigger、`pr_number` 输入、三步表达式均正确。
- 注意：属低风险 additive 改动，无实质权衡，未建 ADR。
